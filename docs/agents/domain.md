# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decisions under `docs/adr/`.

Before exploring the codebase, read the glossary and relevant ADRs.
If they do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

Use the glossary's vocabulary in issues, proposals, and tests.
Surface conflicts with existing ADRs explicitly.
